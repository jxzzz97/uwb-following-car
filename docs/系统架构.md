# 系统架构与模块边界

## 设计目标

系统将 UWB 相对位置转换为四轮差速底盘的左右轮组速度。设计重点是接口清晰、配置集中、输出可追踪和故障可解释。控制核心不依赖 Arduino、网页或某个电机型号。

物理测量方案为全向单天线 Tag + 三天线 Anchor，距离由 DS-TWR 获取，方向由 PDoA 推导。本版 Anchor 的控制用角度只取 PD12，ESP32 采用四状态线性 KF 跟踪。选型依据见[天线与测距测角](天线选型与测距测角原理.md)，跨端流程见[完整数据链路](测量到电机的数据链路.md)，估计模型见[Kalman 设计](Kalman滤波设计与参数整定.md)。

## 固件划分

| 工程 | 责任 | 构建环境 |
| --- | --- | --- |
| `firmware/uwb_cbu5000v210/tag_firmware` | 随身端 UWB 交互 | Keil / ARM Compiler 6 |
| `firmware/uwb_cbu5000v210/anchor_firmware` | 车载测距测角、UART 输出 | Keil / ARM Compiler 6 |
| `firmware/esp32` | 测量处理、控制、电驱、维护接口 | PlatformIO / Arduino ESP32 |

Tag、Anchor 共享 `shared_sdk`；两端独立选择天线布局，不能为了目录对称而统一其硬件宏。

## ESP32 模块与接口

| 模块 | 源码 | 输入 → 输出 | 持有状态 |
| --- | --- | --- | --- |
| 测量接收 | `uwb_parser.cpp` | UART 字节 → `Measurement` | 行缓冲、最近有效帧、统计 |
| 目标处理 | `target_filter.cpp`、`ekf_filter.c` | 测量、安装配置 → `Target` | 四状态估计、最近测量序号 |
| 跟随 | `controller.cpp` | 目标、跟随配置 → `Motion` | 使能、到达滞回、运行状态 |
| 底盘 | `kinematics.cpp` | 前进速度/角速度、几何参数 → `WheelCommand` | 无外部状态 |
| 电驱 | `waveshare_servo.cpp` | 逻辑轮 RPM → 协议帧 | 配置就绪、发送计数 |
| 参数存储 | `parameter_store.cpp` | 停车时的新目标距离 → NVS | 版本化存储命名空间 |
| 诊断 | `web_console.cpp`、`dashboard.h` | 运行快照 → JSON、CSV、网页 | 256 帧日志环形缓冲 |
| 网络维护 | `network_services.cpp` | 本地网络配置 → Wi-Fi / OTA 服务 | 连接和升级状态 |
| 调度 | `main.cpp` | 系统时间、UART、操作 → 模块调用 | 最近控制周期时间 |

头文件 `follow_core.h` 定义核心数据契约。`app_runtime.h` 只连接应用模块，不进入核心算法。若增加另一种电机协议，替换 `motor_driver.h` 的实现，保留相同的轮速和停止语义。

## 时间与控制权

默认控制周期 50 ms。每轮先处理 UWB 与本地操作，再更新控制并发送电机指令，最后处理网络。测量时间戳由接收到完整有效帧的时刻产生。网络不会主动调用轮速控制，网页使能请求交给控制器统一处理。

使能后控制间隔超过 150 ms，控制器撤销使能并记录 `timing_fault`。该判断在软件恢复执行时生效；它不是独立于 MCU 的电机硬件看门狗。

## 迁移策略

同类差速底盘通过车辆几何、能力参数、驱动配置迁移。四轮滑移转向使用有效轮距系数进行实测标定。轴距与车体外形保留为机械几何描述，当前理想差速公式只使用有效轮距与轮径。更换为阿克曼、麦克纳姆等结构时，需要新的运动学实现。
