# 底盘运动学与电驱适配

## 差速运动学

输入前进速度 `v`、向左为正的角速度 `ω`，有效轮距 `B = track_width_cm × effective_track_scale`：

```text
left_cm_s  = v - ω_rad_s × B / 2
right_cm_s = v + ω_rad_s × B / 2
wheel_rpm = wheel_cm_s × 60 / (π × wheel_diameter_cm)
```

因此正角速度对应右轮更快。算法层始终使用物理左右命名，不用交换左右变量来补偿安装问题。内轮速度小于零时置零，超过最大轮速时左右同比例缩放。

车体加宽不等于轮距增加。轮径增大时，相同线速度需要更低 RPM。四轮滑移转向中，轴距、接地材料、负载分布会影响有效转向行为；`effective_track_scale` 是需要试验标定的近似补偿，不替代完整轮胎模型。

## 驱动接口

`motor_driver.h` 定义 `motorBegin()`、`motorApply()`、`motorStop()`。输入是逻辑轮 RPM，正值代表车辆向前。接口实现负责：物理 ID、左右轮组映射、安装方向、传动比、协议范围、报文与停止行为。

新增串口、RS485 或其他伺服驱动时实现同一接口，并核对驱动速度模式、使能过程和停止语义。当前仓库只提供微雪协议参考实现，不将接口抽象等同于所有伺服设备已经兼容。

## 微雪参考适配

`waveshare_servo.cpp` 继承已有工程的 10 字节速度模式协议：速度命令 `0x64`，有符号 RPM 为大端表示，最后一字节为 CRC-8/MAXIM；模式切换 `0xA0` 的末字节为模式值，不采用同样的 CRC 处理。

参考初始化为每个通道发送 5 次速度模式选择，再发送零速制动。帧间间隔 4 ms。参考协议范围配置为 ±330 RPM，只适用于该适配器兼容的协议设备；更换设备应更新协议实现与能力检查。

`MOTOR_CHANNELS` 每项定义：

```cpp
// ID、物理轮组、安装方向、每转一圈车轮所需的电机圈数
{1, WheelSide::Left,   1, 1},
{2, WheelSide::Right, -1, 1}
```

四驱配置可增加第二组左、右通道，每个设备必须使用唯一 ID。上电检查通道数、重复 ID、方向、传动比与最大 RPM，任何不兼容配置都会阻止运动使能。修改配置前确认总线 ID 与实际轮组对应。

## 观测与反馈边界

`MotorOutput` 记录下发的逻辑轮速及发送帧数。本版本不解析电机反馈，所以它不能证明电机已接收到指令、速度已达到目标或不存在故障。物理正反向和空载转动仍需要单独验证。

协议速度上限属于设备边界；最大轮速配置属于车辆能力；跟随请求属于行为层。三者分开，避免修改驱动协议时连带改变跟随逻辑。
